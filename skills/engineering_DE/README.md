# Engineering (DE)

Skills für die tägliche Code-Arbeit. Deutsche Übersetzungen der englischen Originale in `../engineering/`.

- **[diagnose_DE](./diagnose_DE/SKILL.md)** — Disziplinierter Diagnose-Loop für schwierige Bugs und Performance-Regressionen: reproduce → minimise → hypothesise → instrument → fix → regression-test.
- **[grill-with-docs_DE](./grill-with-docs_DE/SKILL.md)** — Grilling-Session, die den Plan gegen das bestehende Domänenmodell herausfordert, Terminologie schärft und `CONTEXT.md` sowie ADRs inline aktualisiert.
- **[triage_DE](./triage_DE/SKILL.md)** — Issues durch eine State Machine mit Triage-Rollen durchführen.
- **[improve-codebase-architecture_DE](./improve-codebase-architecture_DE/SKILL.md)** — Vertiefungsmöglichkeiten in einer Codebasis finden, informiert durch die Domänensprache in `CONTEXT.md` und die Entscheidungen in `docs/adr/`.
- **[setup-matt-pocock-skills_DE](./setup-matt-pocock-skills_DE/SKILL.md)** — Die Repo-spezifische Konfiguration (Issue-Tracker, Triage-Label-Vokabular, Domain-Doc-Layout) aufbauen, die die anderen Engineering-Skills konsumieren.
- **[tdd_DE](./tdd_DE/SKILL.md)** — Test-driven Development mit Red-Green-Refactor-Loop. Baut Funktionen oder behebt Bugs einen Vertical Slice auf einmal.
- **[to-issues_DE](./to-issues_DE/SKILL.md)** — Jeden Plan, jede Spec oder jedes PRD in unabhängig greifbare GitHub-Issues mit Vertical Slices aufteilen.
- **[to-prd_DE](./to-prd_DE/SKILL.md)** — Den aktuellen Gesprächskontext in ein PRD umwandeln und es als GitHub-Issue einreichen.
- **[zoom-out_DE](./zoom-out_DE/SKILL.md)** — Den Agent anweisen, eine Ebene höher zu gehen und breiteren Kontext oder eine übergeordnete Perspektive auf einen unbekannten Code-Bereich zu geben.
- **[prototype_DE](./prototype_DE/SKILL.md)** — Einen wegwerfbaren Prototype bauen, um ein Design auszuloten — entweder eine ausführbare Terminal-App für Zustands-/Business-Logic-Fragen oder mehrere radikal verschiedene UI-Variationen, von einer Route umschaltbar.
