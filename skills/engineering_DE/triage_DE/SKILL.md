# Triage

Issues im projekt-eigenen Issue-Tracker durch eine kleine State Machine mit Triage-Rollen bewegen.

Jeder Kommentar oder jedes Issue, das während der Triage im Issue-Tracker veröffentlicht wird, **muss** mit diesem Disclaimer beginnen:

```
> *This was generated by AI during triage.*
```

## Referenz-Docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — wie man dauerhafte Agent-Briefs schreibt
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — wie die `.out-of-scope/`-Wissensbasis funktioniert

## Rollen

Zwei **Kategorie**-Rollen:

- `bug` — etwas ist kaputt
- `enhancement` — neue Funktion oder Verbesserung

Fünf **Zustands**-Rollen:

- `needs-triage` — Maintainer muss evaluieren
- `needs-info` — wartet auf mehr Informationen vom Melder
- `ready-for-agent` — vollständig spezifiziert, bereit für einen AFK-Agent
- `ready-for-human` — benötigt menschliche Implementierung
- `wontfix` — wird nicht umgesetzt

Jedes triagierte Issue sollte genau eine Kategorierolle und eine Zustandsrolle tragen. Wenn Zustandsrollen in Konflikt stehen, das markieren und den Maintainer fragen, bevor etwas anderes getan wird.

Das sind kanonische Rollennamen — die tatsächlich im Issue-Tracker verwendeten Label-Strings können abweichen. Das Mapping sollte bereitgestellt worden sein — `/setup-matt-pocock-skills` ausführen, wenn nicht.

Zustandsübergänge: Ein unbeschriftetes Issue geht normalerweise zuerst zu `needs-triage`; von dort bewegt es sich zu `needs-info`, `ready-for-agent`, `ready-for-human` oder `wontfix`. `needs-info` kehrt zu `needs-triage` zurück, sobald der Melder antwortet. Der Maintainer kann jederzeit übersteuern — ungewöhnliche Übergänge markieren und vor dem Fortfahren fragen.

## Aufruf

Der Maintainer ruft `/triage` auf und beschreibt in natürlicher Sprache, was er möchte. Die Anfrage interpretieren und handeln. Beispiele:

- „Zeig mir alles, was meine Aufmerksamkeit braucht"
- „Lass uns Issue #42 ansehen"
- „Verschiebe #42 auf ready-for-agent"
- „Was ist bereit für Agents zum Aufgreifen?"

## Was Aufmerksamkeit braucht anzeigen

Den Issue-Tracker abfragen und drei Buckets anzeigen, älteste zuerst:

1. **Unbeschriftet** — noch nie triagiert.
2. **`needs-triage`** — Evaluation im Gange.
3. **`needs-info` mit Reporter-Aktivität seit den letzten Triage-Notizen** — erneute Evaluation nötig.

Anzahlen und eine einzeilige Zusammenfassung pro Issue anzeigen. Maintainer auswählen lassen.

## Ein spezifisches Issue triagieren

1. **Kontext sammeln.** Das vollständige Issue lesen (Body, Kommentare, Labels, Melder, Daten). Frühere Triage-Notizen parsen, damit aufgelöste Fragen nicht neu gestellt werden. Die Codebasis mithilfe des Domänenglossars des Projekts erkunden, ADRs in dem Bereich respektieren. `.out-of-scope/*.md` lesen und frühere Ablehnungen sichtbar machen, die diesem Issue ähneln.

2. **Empfehlen.** Dem Maintainer die empfohlene Kategorie und den Zustand mit Begründung nennen, plus eine kurze Codebasis-Zusammenfassung zum Issue. Auf Anweisung warten.

3. **Reproduzieren (nur Bugs).** Vor dem Grillen eine Reproduktion versuchen: die Schritte des Melders lesen, den relevanten Code verfolgen, Tests oder Befehle ausführen. Berichten, was passiert ist — erfolgreiche Reproduktion mit Code-Pfad, fehlgeschlagene Reproduktion oder unzureichende Details (ein starkes `needs-info`-Signal). Eine bestätigte Reproduktion ergibt einen viel stärkeren Agent-Brief.

4. **Grillen (wenn nötig).** Wenn das Issue weiter ausgearbeitet werden muss, eine `/grill-with-docs`-Session starten.

5. **Das Ergebnis anwenden:**
   - `ready-for-agent` — einen Agent-Brief-Kommentar posten ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human` — gleiche Struktur wie ein Agent-Brief, aber notieren, warum es nicht delegiert werden kann (Ermessensentscheidungen, externer Zugang, Design-Entscheidungen, manuelles Testen).
   - `needs-info` — Triage-Notizen posten (Vorlage unten).
   - `wontfix` (Bug) — höfliche Erklärung, dann schließen.
   - `wontfix` (Enhancement) — in `.out-of-scope/` schreiben, darauf aus einem Kommentar verlinken, dann schließen ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).
   - `needs-triage` — Rolle anwenden. Optionaler Kommentar bei teilweisem Fortschritt.

## Schnelle Zustandsüberschreibung

Wenn der Maintainer sagt „verschiebe #42 auf ready-for-agent", vertrauen und die Rolle direkt anwenden. Bestätigen, was getan werden soll (Rollenänderungen, Kommentar, Schließen), dann handeln. Grillen überspringen. Wenn zu `ready-for-agent` ohne Grilling-Session verschoben wird, fragen, ob ein Agent-Brief geschrieben werden soll.

## Needs-Info-Vorlage

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

Alles, was während des Grillens aufgelöst wurde, unter „established so far" erfassen, damit die Arbeit nicht verloren geht. Fragen müssen spezifisch und handlungsorientiert sein, nicht „bitte mehr Infos geben".

## Eine vorherige Session fortsetzen

Wenn frühere Triage-Notizen zum Issue vorhanden sind, diese lesen, prüfen, ob der Melder ausstehende Fragen beantwortet hat, und ein aktualisiertes Bild präsentieren, bevor weitergemacht wird. Aufgelöste Fragen nicht neu stellen.
